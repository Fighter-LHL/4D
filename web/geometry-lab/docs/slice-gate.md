# 球门：先拨一颗球，再进庭院

2026-10-23。本轮只检验一个产品假设：先让玩家拨动一颗球的截面，能否帮助他们在进入「中转站·两种办法」后，预期出口球随 W 变化的样子。判定仍按 [G0–G2](../../../docs/mechanic-validation.md) 做真人试玩。

## 已实现

首页「先走球门」进入 `?level=gate`，旁边的「试玩两种办法」直接进入庭院。球门开着地图，目标只有「走到东边的出口。」没有开场卡或预测题，三级提示由玩家主动点开。

通关卡显示「球没有消失，你换到了它外面的一层。」可进入两种办法，也可进入 `?level=gate-blind`。后者共用同一个 `GATE_ROOM`，沿用 `map: 'hidden'` 和主动查看空间结构的规则；完成卡不显示成绩，直接提供进入庭院的按钮。

视觉沿用现有界面：板墙使用 role 2，球使用 role 7。房间只含两道固定侧墙、一颗超球和一道相位板墙。庭院几何、两条路线的原有测试和 `LEVELS_LIST` 十关顺序保持原样。

## 几何与搜索

| 项目 | 参数 |
| --- | --- |
| 出生点 / 出口 `(x,z)` | `[-2.35,0]` / `[2.85,0]` |
| 超球中心 `(x,y,z,W)` / 半径 | `[0,0.55,0,0.8]` / `0.95` |
| 板墙中心 / W 范围 | `[1.55,0.75,0,0]` / `[-0.55,0.55]` |
| 窄道内侧 | `z = ±0.65`，角色半径 `0.22` |
| 出口有效层 | `goalW: [-0.25,0.25]` |

半径 `0.85 / 0.95 / 1.05` 均经过搜索和吞没采样；选用 `0.95`，在初始 W=0 时已有半径约 `0.512` 的可见截面，在 W=0.8 达到最大，向两端移动均可消失。

搜索步长沿用现有测试：平面 `0.08`、W 方向 51 档。存在中途改 W 的走法，51 个固定 W 样本均不能完成。此结论包含出口的 `goalW` 条件：冷层可以穿过窄道，但抵达出口后必须回到中间层。测试也确认，放宽 `goalW` 后冷层可直走，避免把出口条件误报为通道本身的性质。

出生区域在 `x ∈ [-2.7,-1.7]、z ∈ [-0.6,0.6]` 的 25 个采样点都能扫过 W 的完整范围。窄道测试覆盖球附近九个点、板墙内三个点及板墙后的三个点；会吞没角色的请求被拒绝，即使换层的两个端点都没有球，也不能穿过中间会胀大的截面。碰撞继续使用当前截面和 `wChangeEngulfs`。

## 本地验证

- 现有 71 项与新增 6 项测试合计 77 项全部通过。全部 `.mjs` 的 `node --check` 通过。
- 浏览器从首页进入球门，实际拖动滑轨观察胀缩；经窄道到出口后进入庭院，完成既有的直接携核运送路线。
- 检查了球门两条通关分支、隐藏地图版本到庭院的跳转、首页庭院快捷入口，以及两个新关卡的直达链接。
- 隐藏地图版本默认没有地图、红区或 W 轮廓。拒绝换层时只短暂显示阻挡物的地面轮廓；主动查看后地图和辅助出现，五秒后收起。
- 1440×900 桌面与 390×844 手机布局已检查；手机通关卡按钮没有横向溢出。球门、隐藏地图重走和庭院完成后，静止采样期间动画帧计数均不再增长。控制台错误为 0。

证据在仓库根目录的 `output/playwright/slice-gate/`：`tests.tap` 保存完整测试输出，`radius-samples.json` 保存三种半径的搜索与采样结果。最新浏览器复核放在 `recheck/`，包含 `browser-results.json`、`console-errors.log` 和流程截图；报告同时记录被测源码的 SHA-256。六处静止检查的动画帧计数均未增长，待执行帧数均为 0。

本次没有可用的 Local Codex 浏览器连接，使用 `/tmp/wslice-check` 的 Playwright 与本机 Chrome。启动预览后可执行 `node output/playwright/slice-gate/check.cjs` 重跑。脚本通过键盘和鼠标拖动滑轨操作，附加的观察器只读取状态与渲染帧。

这些结果证明关卡可玩且保留了现有规则。约一至两分钟仍是体验目标，尚未测量真实玩家耗时。真人试玩还需观察：玩家能否发现 W 与截面的关系、说明球为何消失，以及在下一次改 W 前预期球的变化；进入庭院后是否仍盲扫滑轨，也应单独记录。G0–G2 尚未判定。
