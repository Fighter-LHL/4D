## 2. 设计方向

保留原作的抽象空间与晶体主题，把中转站做成一座**克制的微缩机关庭院**：

- 场景是视觉中心，HUD 是围绕场景的仪表带，而不是另一套内容页。
- 用真实几何截面表达机关，不用浮层图标替代碰撞。
- 颜色只做辅助。门扇是否出现、墙带是否仍有截面、门槛是否留存，才是可读的因果。
- 机关标签只在靠近时出现，避免把地图做成常驻说明书。
- 完整解法不自动出现；提示仍然由玩家主动请求。

## 3. 视觉规则

### 3.1 色与材质

| 语义 | 主色 / 材质 | 行为 |
| --- | --- | --- |
| 冷蓝供电 | `#57c9e6`、蓝线、冷蓝门槛 | 插座亮起，线路与北门同线；供电门从碰撞体移除。 |
| 相位墙 | 红纹矿带 `#ff8f6e`，通电时加冷蓝墙缘 | 只在自身 W 范围实心；供电不会自动移除它。 |
| 回廊 | 黄铜 / 金色门槛 `#f0c978` | 手动拉开后锁存；断电不回收。 |
| 未通电北门 | 暗铜门扇 `#8d5f3f`，暗 ribs | 默认封闭；通电后消失，露出后面的相位墙。 |
| 永久隔断 | 石台、冷影脚线 | 始终存在，不参与机关状态。 |

关键改动：给供电门和相位墙建立**前后层次**。未通电时，暗铜供电门在视觉命中顺序上略向前偏置 `0.035`，让玩家先看到“关着的门”；通电后供电门消失，红纹相位墙仍在，并通过通电墙缘说明“电到了，但这面墙还没让开”。该偏置只影响绘制排序，不进入碰撞或游戏判定。

### 3.2 场景与 HUD

- 16:10 左右的浮动石台，柔和方向光，低对比阴影。
- 五层 W 色带从冷蓝过渡到暖橙，地图平面与场景同步。
- 角色、晶核、插座、回廊开关、接收台使用青绿 / 冷蓝 / 黄铜三类局部光。
- 顶部只保留关卡、目标、状态和工具；侧栏按“地图 → 机构读数 → 键位”排列。
- 机构读数面板显示当前三件事：供电、相位墙、回廊。它只描述现在，不提示下一步。

### 3.3 标签与焦点

- 插座、回廊开关标签在水平距离 `≤ 1.55` 且 W 接近时出现。
- 晶核标签：可拿取时显示“按空格拿起”；换层后不可见时，在近距离显示“留在 W …”。
- 接收台标签在接近或未移动时出现。
- 鼠标点击提示按钮后，焦点交还场景；之后按空格是拿取 / 互动，不会再次升级提示。键盘激活提示按钮时保留按钮焦点，Tab / Enter 仍正常。

### 3.4 响应式

| 视口 | 结果 |
| --- | --- |
| 1440×900 | 场景 1057×810，侧栏 331×812，页面无滚动。 |
| 1280×720 | 场景 934×630，侧栏 294×632，页面无滚动。 |
| 834×760 | 场景 544×645，侧栏 248×647；地图、机构读数、键位仍在首屏。 |
| ≤ 820 | 单列：场景在上，地图和机构读数在下，避免窄屏三栏挤压。 |

### 3.5 动效

- 动效只由真实状态变化触发：拿取、放下、供电、开门、拒绝换层、送达。
- 静止时不持续请求动画帧；退回标题后也不保留渲染循环。
- 尊重 `prefers-reduced-motion`：关闭 CSS 动画/过渡，W 变化直接落位。

## 4. 六状态

图板：`states.html`。六帧来自同一次连续键盘通关；第六帧之后继续走到接收台并触发胜利。

| # | 状态 | 画面 W | 触发 | 视觉反馈 | 碰撞事实 |
| --- | --- | --- | --- | --- | --- |
| 01 | 初始 | 0.00 | 打开 `?level=station` | 暗铜北门、未亮蓝线、金色接收台 | 未通电供电门 + 同层相位墙共同封闭 |
| 02 | 携带 | 0.00 | 靠近晶核按空格 | 手中青色晶核、状态“携带晶核” | 携带半径 0.40，仍不能过北门 |
| 03 | 供电但相位墙仍在 | −1.09 | 到蓝层插座放入晶核 | 蓝线亮起，暗铜门消失，红纹相位墙 + 冷蓝通电框 | 供电门移除；相位墙在 W −2.0…+0.7 仍实心 |
| 04 | 暖层可穿 | +0.76 | 空手把 W 推到暖层 | 相位墙在当前截面消失，北门成为空洞 | +0.76 超出相位墙上界 +0.70，可通过 |
| 05 | 回廊保持开启 | −0.04 | 到另一侧中间层拉开回廊 | 回廊门消失，金色门槛留存，开关亮起 | 回廊门锁存并永久移出碰撞 |
| 06 | 取回后北门关、回廊留 | −1.07 | 经回廊返回插座取回晶核 | 蓝线熄灭，暗铜北门恢复，金色门槛仍在 | 供电门碰撞恢复；回廊锁存不受断电影响 |

### 6.2 浏览器连续通关

用真实键盘流程完成：

`拿取晶核 → 蓝层插座 → 供电但相位墙仍实心 → 暖层穿过 → 另一侧回廊锁存 → 回廊返回 → 取回晶核 → W0 送达接收台`

逐帧核对的实际页面状态：

- 03：`W −1.09`，供电 `已接通`，相位墙 `实心`，回廊 `关闭`。
- 04：`W +0.76`，供电 `已接通`，相位墙 `已让开`，回廊 `关闭`。
- 05：`W −0.04`，供电 `已接通`，相位墙 `实心`，回廊 `已锁存`。
- 06：`W −1.07`，供电 `未接通`，相位墙 `实心`，回廊 `已锁存`。
- 之后带晶核回到 W0，接收台触发胜利；没有停在第五帧假定成功。

为稳定驱动方向，验证期间临时使用只读坐标探针；它不修改碰撞或输入，交付前已移除。

### 6.3 提示、镜头、重开与空闲

- 鼠标点击提示后，焦点回到场景；`1/3` 提示保持为 `1/3`，随后按空格成功拿起晶核（未被升级成下一条提示）。
- 拖动场景后点击“视角复位”，镜头回到默认视角，焦点回到场景。
- 按 `R` 重开：位置回到 `(-2.55, 0.9)`，空手，提示回到 `0/3`。
- 静止 1.4 秒：RAF 请求数 `3 → 3`，pending `0`。
- 退回标题后静止 1.5 秒：RAF 请求数 `47 → 47`，pending `0`；再次进入场景正常。
- `prefers-reduced-motion: reduce`：W 可以移动到约 `+0.51`，静止后 RAF 请求数 `18 → 18`，pending `0`。

### 6.4 布局与控制台

- 三个视口均无页面级横向或纵向滚动；场景、地图、机构读数、键位可见。
- 直接试玩入口标题为「中转站」，目标为「把晶核送到隔墙另一侧的接收台。」，机构初始为 `未接通 / 实心 / 关闭`。
- 所有核对会话中 `console error = 0`、`pageerror = 0`。
- `states.html` 在 1440×900 与 834×760 下六帧齐全、图片全部加载、无横向溢出。

## 7. 未验证项与限制

- 只在本地 Chrome + SwiftShader 中自动核对；未在 Safari、Firefox、真实 GPU、iOS/Android 触屏设备上逐项回归。
- 834×760 是桌面浏览器视口模拟，没有计算真实平板的浏览器工具栏占高。
- 键盘流程已完整验证；屏幕方向键（dpad）、触摸拖动和屏幕阅读器语义未做真机测试。页面已有 aria 标签和焦点样式，但不能据此声称完整无障碍验收。
- 音效开关存在，但本轮未做听感或音量审计。
- 长时间游玩的内存/帧率曲线未做 profiling；只验证了静止与标题页不新增 RAF。
- `states.html` 是静态设计图板，不与游戏实时联动；六帧是连续通关的截图记录，不是自动截图测试。
- 视觉命中偏置只用于让未通电门扇与相位墙的前后关系可读，不改变碰撞；若后续调整场景物件贴得很近，需要重新检查排序观感。
