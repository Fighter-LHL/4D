## 2. B 版实现规格

以下是**待实现合同**，不是已完成的 B 版验证结果。固定版本所需的输入、几何、运行时和音效文件均已读到，无源码读取缺口。

### B.7 按住意图状态机

**职责：**

- `controls.mjs`：输入意图、停靠候选、参数与纯函数。
- `app.mjs`：事件所有权、状态切换、动画调度、反馈触发。
- `game.mjs`：继续承担真实移动、交互与运行状态。
- `geometry.mjs`：继续作为碰撞与 W 扫掠的唯一依据。

现有问题是 `app.mjs` 受阻后执行 `wHold = 0`，重复 `keydown` 又被忽略；B 必须把“仍在按”和“实际能移动”拆开。[现有输入循环与事件](https://github.com/Fighter-LHL/4D/blob/359ea294b8934f1d61473e3ae47247e56a406d75/web/geometry-lab/app.mjs)

#### 状态定义

| 状态 | 含义 | W 行为 |
|---|---|---|
| `IDLE` | 没有 W 输入或自动停靠 | 保持当前位置 |
| `DRIVING` | 持有一个净方向 | 按速度申请连续位移 |
| `BLOCKED` | 仍持有方向，但受阻 | 停在安全边界，保留意图 |
| `NEUTRAL` | 正负方向同时持有 | 不推进，不触发松手吸附 |
| `DOCKING` | 正常松手后执行短距离停靠 | 逐帧安全推进，可随时取消 |
| `LOCKED` | 阻断卡片、离开页面或关卡结束 | 清空输入，等待新的有效按下 |

#### 必须维持的输入规则

- Q/E 使用按键集合管理，忽略重复 `keydown`；Q 与 E 同按时净方向为零，释放其中一个后恢复剩余方向。
- 受阻、恢复都不结束手势；不在这两个转移点调用 `endWGesture()`。
- W 与地面方向可以同时持有。地面移动后，按**新位置和新的 `activeField()`**重新判断 W。
- 不强迫玩家同时操作两个方向；“先站稳、再换 W”始终成立。
- 一个 W 手势只由一个输入来源持有；其他来源不能叠加速度。新的 W 输入可以中断自动停靠。
- 触屏 W 按钮使用独立 `pointerId`，允许与地面方向按钮同时按。**不能照抄滑轨现有的 `!event.isPrimary` 拒绝条件**，否则第二个触点可能失效。
- 地面 WASD 的方向映射、速度和沿墙滑动规则保持原样。

#### 消除松手后的尾随歧义

B 的人工输入采用以下不变量：

> 每次申请经 `reachDial()` 接受后，同帧同步 `run.dial`、`current` 和 `target`；尚未执行的自动停靠终点单独保存在 `dockGoal`。

Q/E 本来就按帧时间产生连续位移，不再叠加一次显示尾随；滑轨直接跟随其安全接受位置。这样，正常松手可以停在玩家实际看到的位置，快速拖动也不会因取消尾随而被吞掉。

自动停靠采用独立短动画，每帧重新检查当前位置到剩余目标的扫掠安全性。保留现有 `sweptSections()` 等保护，不直接改写 `run.dial` 绕过运行时。

#### 条目化伪代码

以下控制器名称为拟新增名称，`reachDial()`、`canSetDial()`、`activeField()` 是已有机制。

```text
有效 W 按下：
    若 LOCKED，忽略
    若正在 DOCKING，取消未执行停靠，结束旧手势
    注册来源与按键/指针
    若这是新手势，记录起点和当前 fieldEpoch
    根据净方向进入 DRIVING 或 NEUTRAL

每次推进：
    读取最新位置、携带状态、机关状态和 activeField
    若受阻且这些条件均未变化，不重复申请同一个无效位移
    按 B.8 选择一般速度或近身速度
    accepted = run.reachDial(请求位置)
    同步实际 W 与显示 W

    若被截停：
        进入 BLOCKED，保留按住意图
        仅按 B.10 的接触边沿触发反馈
    否则：
        进入 DRIVING
        根据实际脱离位移重新武装接触反馈

所有 W 输入正常释放：
    停止人工推进
    以当前实际 W 重新计算停靠资格
    若符合 B.8/B.9，进入 DOCKING
    否则结束手势并进入 IDLE

取消事件：
    撤销 dockGoal 和输入所有权
    不进行吸附，不补发位移
    结束手势一次
    根据事件进入 IDLE 或 LOCKED
```

#### 各事件清理合同

| 事件 | 清 W 输入 | 清地面按住 | 可吸附 | 其他处理 |
|---|---:|---:|---:|---|
| 最后一个 W 键正常 `keyup` | 是 | 否 | 是 | 停靠结束或取消后统一结束手势 |
| W 按钮／滑轨正常 `pointerup` | 是 | 否 | 是 | 释放指针所有权 |
| W 的 `pointercancel`／非正常丢失捕获 | 是 | 否 | 否 | 取消该 W 手势全部未执行动作 |
| `window.blur`、页面变为 hidden | 是 | 是 | 否 | 取消停靠；恢复可见后不恢复旧按住状态 |
| 阻断卡片、重开、切关、回标题、通关 | 是 | 是 | 否 | 清旧关反馈计时、回调和输入代次 |
| 拾取、放下、插入、取回、拉回廊 | 保留仍真实按住的方向 | 否 | 本手势禁用 | 取消停靠，增加 `fieldEpoch`，重新计算实际碰撞 |
| 停靠中开始新的人工 W 输入 | 旧手势清理 | 否 | 取消旧吸附 | 新输入立即取得控制 |

`pointerup` 后正常发生的 `lostpointercapture` 必须幂等，不能再次统计或再次吸附。

取消过程只撤销未来动作，**不得调用可能触发交付的 `requestDial(current, true)` 清理路径**；该路径当前会调用 `run.step()`。取消本身不得改变 XYZ、携带状态或机关状态。[`requestDial()` 与运行时交互](https://github.com/Fighter-LHL/4D/blob/359ea294b8934f1d61473e3ae47247e56a406d75/web/geometry-lab/game.mjs)

### B.8 近身停靠：对象、范围与参数

**首轮只接受两种停靠对象：**

- `relay.socket`：携带晶核准备放入，或插座当前已有晶核可取回。
- `relay.latch`：回廊尚未打开。

“已知”采用可执行判据：**该机关在当前 W 中实体可见，角色处于其真实交互距离内，而且当前状态仍有交互意义。**异层淡影、远处刻度、曾经看过的位置都不足以自动吸附。

#### 参数冻结表

| 参数 | 初始值 | 本轮上下限／调整边界 |
|---|---|---|
| 一般方向速度 | **1.28 W/秒【现，换算自 `W_RATE=0.32`】** | 首轮不调整 |
| 插座中心与有效窗 | **−1.1；±0.25 W【现】** | 不得改动 |
| 回廊开关中心与有效窗 | **0；±0.30 W【现】** | 不得改动 |
| 两机关地面交互距离 | **0.58【现】** | 直接读取 `device.reach`，不得另造扩大范围 |
| 松手捕获半径 | **0.12 W【现值，B 初始沿用】** | 预试允许 **0.08–0.18 W【试】**；正式期间冻结 |
| 近身方向速度 | **0.50 W/秒【试】** | 预试允许 **0.40–0.625 W/秒【试】** |
| 插座有效窗经过时间 | **1.00 秒【试，0.50÷0.50】** | 对应上述速度为 **0.80–1.25 秒【试】** |
| 回廊有效窗经过时间 | **1.20 秒【试，0.60÷0.50】** | 同一局部速度，不另设一套控制 |

#### 三类输入的统一范围

- 键盘松手、触屏 W 按钮松手、滑轨松手：**同一候选、同一捕获半径、同一扫掠检查、同一取消规则**。
- 近身限速用于方向持有输入。
- 滑轨保持绝对位置跟手，不再附加方向限速；它与方向按钮统一的是释放规则。
- 有效窗口内即可交互，不要求吸到中心后才出现动作按钮。
- 每次释放最多选择一个候选；若候选有歧义，取消自动吸附。
- 停靠完成后不锁住玩家，新的方向输入立即离开。

### B.9 禁止吸附的情况

以下全部直接拒绝自动吸附，保留实际释放位置：

1. 目标来自门洞最佳 W、球体消失点、色带中心、全局 W=0、接收台或自由放下的晶核。
2. 当前关卡为 `map: 'hidden'`；临时展开地图也不启用自动停靠。
3. 机关仅显示异层淡影，或角色不在真实 `reach` 内。
4. 超出捕获半径，或机关当前已无交互意义。
5. 释放发生于取消、失焦、页面隐藏、切关或阻断界面。
6. 本手势期间携带半径或机关状态改变。旧候选作废；下一次新的 W 手势才重新取得吸附资格。
7. 从实际位置到候选的**整个 W 区间**存在吞没风险。
8. 停靠过程中失去近身条件、状态改变、扫掠不再安全或收到新 W 输入。

人工移动可以停在障碍边界；**自动吸附预检失败时直接取消，不自动改找另一个点，也不把人拉到障碍边缘。**安全判定只调用当前 `activeField()` 与既有几何函数。[`safeWToward()`、`wChangeEngulfs()`](https://github.com/Fighter-LHL/4D/blob/359ea294b8934f1d61473e3ae47247e56a406d75/web/geometry-lab/geometry.mjs#L533-L590)

### B.10 碰壁／吞没拒绝反馈

**一次连续接触只启动一次反馈。**持续顶住时继续做安全检查，但不重复设置闪光、不续期轮廓、不反复播音。

重新触发的条件：

- 新手势；或
- 已脱离阻挡，累计产生至少 **0.02 W 的安全位移【试】**，随后再次受阻。

这与统计分开：`wRefused` 仍沿用**每个手势最多一次【现】**的含义；接触反馈重新武装不调用 `endWGesture()`。

| 项目 | B 版合同 |
|---|---|
| 场景定位 | 角色已有脚环短亮，并显示实际拒绝物的既有轮廓；不得绘制推测安全区 |
| 脉冲时长 | **200 毫秒【试】**；预试范围 **120–300 毫秒【试】** |
| 隐图轮廓 | 沿用 **1600 毫秒【现，`NUDGE_MS`】**，一次接触不续期 |
| 音效 | 沿用 `sfx.refused()`，**120 毫秒【现】**；静音时只做视觉反馈 |
| 音效最小间隔 | 沿用 **700 毫秒【现】**；只在真正播放时更新时间戳，不排队补播 |
| 文案 | 空手：“沿W会碰到障碍”；携带：“晶核会碰到障碍” |
| 文案长度／时长 | 最长 **12 个显示字符【试，含字母和标点】**；显示 **1200 毫秒【试】** |
| 文案位置 | 沿用场景内 `#toast`：桌面下方居中、窄屏左上；不放在滑轨旁 |
| W 达到两端 | 仅显示到端状态，不记吞没拒绝，不播放撞墙音 |

同一帧同时发生地面受阻与 W 拒绝时，优先播放 W 拒绝反馈，避免叠音。仅删除 `wHold=0` 会造成现有 `refuse()` 和轮廓计时反复触发，因此必须同时改反馈边沿逻辑。[`app.mjs`、`sfx.mjs`](https://github.com/Fighter-LHL/4D/tree/359ea294b8934f1d61473e3ae47247e56a406d75/web/geometry-lab)

### B.11 滑轨与精确读数

**B 默认显示：**±W 方向、当前位置、连续色带与纹理、Q/E 操作说明、触屏 W 按钮、真实可交互状态。

**B 默认隐藏：**精确 W 小数、“第几层”的编号、细步进快捷键说明、远处机关的自动停靠暗示。

细步进决定如下：

- **保留为隐藏高级输入，不关闭。**
- 滑轨获得键盘焦点时，保留方向键 **0.02 dial＝0.08 W【现】**、PageUp/PageDown **0.1 dial＝0.4 W【现】**及 Home/End。
- 这些输入仍走统一安全通道，松手按 B.8/B.9处理。
- 保留滑轨的键盘可达性和 ARIA 数值；不因视觉隐藏而删除无障碍语义。
- 日志区分 `keyboard-hold`、`rail-keyboard`、`rail-pointer`、`touch-w-button`。
- 触屏 W 按钮使用 **48×48 CSS 像素【试】**的点击区域，放在现有控制区，不改变主场景相机或画布取景尺寸。

统一定义：

- **吸附干扰：**有证据表明系统把玩家拉离原定停点或阻碍其继续经过；仅看到反向操作不能自动判定。

### D.22 决策树

**按顺序执行，只进入第一个满足的分支。下面所有人数、次数和差值均为【试：待试玩决策初值】。**

定义：

- `Gk_B`：B 组该门禁通过人数。
- `Hard_A / Hard_B`：各组停靠负担参与者人数。
- `Snap_B`：B 组吸附干扰参与者人数。
- `Info_B`：在至少两个决策点，经原话或行为确认“不知道应观察什么／为什么要换 W”的人数。

```text
0. IF 出现任何一次穿墙、取消后持续移动、状态损坏：
       THEN 修实现，受影响会话单列；暂不判断方案优劣。

1. ELSE IF 任一组不足5名可判定首次样本，
           或关键G2/G4证据不足以判断是否过线：
       THEN 保留探索性结论，按A.2降级或补证据；不启用备选。

2. ELSE IF Info_B >= 3，
           或 G1_B <= 2，
           或 G2_B <= 2，
           或 G4_B <= 1，
           或 B的G2/G4比A少至少2人：
       THEN 转关卡信息设计；
            检查观察对象、局部因果和必要反馈，不以自动停靠代替理解。

3. ELSE IF Snap_B >= 2：
       THEN 调吸附；
            优先改捕获半径、局部速度或取消规则，保持几何与提示不变；
            修订版重新编号，不能沿用本轮通过结论。

4. ELSE IF G0_B、G1_B、G2_B、G3_B均 >= 4，G4_B >= 3，
           且两组各至少4人取得两次有效停靠机会，
           且 Hard_A >= 3、Hard_B >= 3、Snap_B <= 1：
       THEN 允许研究性启用E.24“下一已知停靠”备选。

5. ELSE IF B达到全部门禁，
           且两组各至少4人取得两次有效停靠机会，
           且 Hard_B <= 1、Snap_B <= 1，
           且 B的G2/G4各自不比A少超过1人：
       THEN 保留B。
            若Hard_A >= 3，可写“减负获得方向性支持”；
            若A/B本来都轻松，只写“B可用，优越性尚未确认”。

6. ELSE：
       THEN 暂不切换默认方案；
            指明是停靠机会不足、混合失败还是个别门禁未过，
            做针对性复查，不自动启动备选。
```

若 `Hard_B` 明显高于 A，先查 B 自身的输入与停靠实现；这个结果不能证明连续控制本身需要被替换。

## 5. 备选启用条件 + 红线检查表

### E.24 “单按前往下一已知停靠”的合同

**唯一启用条件：D.22 第 4 分支成立。**其他结果均不触发此备选。

为避免同时引入点按／长按识别延迟，研究版可提供两个明确的停靠按钮，支持点击、触屏及键盘激活；Q/E 保留 B 的连续控制。

停靠位定义：

- 只来自当前关卡的 `socket`、`latch`。
- 该次关卡中，玩家曾进入其近身可交互状态或实际操作过它，才登记为已知。
- 发起移动时仍须处于该机关的地面 `reach` 内，并且机关仍有交互意义。
- 选择指定 W 方向上的最近已知机关位置；没有候选就不可用。
- 不登记色带中心、门洞、球体生灭点、出口 W 或求解器结果。
- 隐图关禁用；重开、切关清除登记。

执行合同：

1. 按一次后，连续显示前往目标的截面变化。
2. 先检查完整扫掠，随后每帧按实际位置和 `activeField()` 重检。
3. 碰到障碍，停在合法边界并结束自动移动；不自动恢复、不改找其他目标。
4. 新的 Q/E 输入立即取消自动移动，并按新方向接管；取消按钮、失焦、触控取消和切关同样终止。
5. 拿放或机关状态改变立即取消，重新按下才可发起新移动。
6. 自动移动不能顺带拾取、放置、开关或交付；这些仍遵守既有运行时规则。

本轮 **12 人【试】**完成后，可用同一批人检查备选的取消和手感，但不能把重玩记作新手 G0/G4；备选升级为默认需要下一轮独立首次体验证据。
