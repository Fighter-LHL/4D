# W / SLICE：浏览器小游戏

一个让人在二维屏幕上看懂第四维的网页小游戏。代码在 `web/geometry-lab/`，纯静态、零依赖，是项目当前的主线（Unity 工程 `WSliceProto/` 只保留为历史参照）。

## 启动

```bash
./scripts/preview-geometry-lab.sh          # 打开 http://127.0.0.1:4175
LAB_PORT=4180 ./scripts/preview-geometry-lab.sh   # 端口被占用时
```

只需要 Python 3 和支持 WebGL 的浏览器；没有 npm 包、CDN、字体下载或远程服务。模块必须经 HTTP 加载，请用启动脚本。`?level=1-2` 可以直接打开某一关（方便试玩和分享），进度保存在浏览器 localStorage。

## 设计：从「看得懂」出发

### 调研结论

| 参考作品 | 让人看懂 4D 的做法 | 我们采用的形式 |
|---|---|---|
| 4D Toys、4D Miner、Bailey Snyder《Interactive 4D Handbook》 | 先当二维小人看三维世界（全部看得见），再用同一套规则升一维 | 第 0 章「扁平国」 |
| 4D Golf（Map / Volume view） | 把 ana-kata（W）画成屏幕上下方向，整关全貌一眼可见 | 「W 地图」+ 竖直 W 滑轨 |
| Miegakure | 把 4D 讲成平行世界的叠层；按 W 区间给地面换纹理 | 五个「层」，各有色调与花纹 |
| 4D Golf 评测共识 | 第四维要成为解题的动词，而不只是背景 | 每个行走关卡都经测试证明必须换 W |

### 关键观察：玩法空间本来就是 (x, z, W)

光点只在地面 (x, z) 上走，墙有多高不影响通行，所以每一关的完整状态空间是三维的 **(x, z, W)**。这带来两件事：

1. 可以**如实画出完整关卡**：把每个物体在行走高度上切开、保留全部 W，得到的是普通的三维方块或球（`wFootprint`）。W 画成竖直方向，当前切片是一块会上下移动的发光平面。
2. 扁平国（二维光点 + 隐藏的第三维）与四维关卡在数学上**完全同构**。第 0 章和第 1 章共用同一组 (x, z, W) 布局，扁平国里信任的那张「全貌」图，升一维后就是 W 地图，只是竖轴从「上下」改名为 W。

### 让 W 可读

- **W 地图**：物体是玻璃体，竖直方向是它占据的全部 W；平面上实时画出当前截面（光线与平面求交后判断点是否在物体内）。光点是平面上的亮点，配一条贯穿所有 W 的虚线，意思是「你可以沿这条线移动」；终点是一段只存在于中间层（`goalW`）的金色光柱（其余层为虚线导引），意思是「必须回到出口所在的那一层才能通关」。
- **层纹理**：W ∈ [−2, 2] 分成五层，冷蓝（−W）→ 淡紫（0）→ 暖琥珀（+W），花纹依次是点阵、斜线、方格、三角网、同心圆。主画面的地面跟着当前 W 换花纹（跨层时渐变），地图侧壁和滑轨用同一套色带，物体按自己的 W 中心着色。层只是视觉辅助，几何与碰撞不读取它。
- **竖直滑轨**：滑轨贴在地图右侧、竖直摆放，方向与地图竖轴一致。`Q` / `E`（或 PageUp / PageDown）调 W，方向键 / WASD 按镜头朝向走路，扁平国保留屏幕轴。拖完滑轨后键盘焦点回到画面。拖动转视角、滚轮缩放，“视角复位”同步恢复主场景和地图的朝向；`R` 或“重来”重置关卡。
- **W 辅助**：滑轨红区（这个 W 会把光点包进墙里）、W 地图上的红色光点线、地面上其他 W 层物体的虚线轮廓，都由 `blockedWIntervals` / `exclusionRadius` 精确算出。超球的虚线圆是它在任何 W 下能碰到光点的最大范围，超球缩小时圆仍留着。第 2 章只在窥视时显示这些辅助；换 W 被拒绝时，只在地面显出挡住光点的那几个物体的虚线轮廓 1.6 秒并平滑淡出（不露出滑轨红区，也不计入窥视）。拖动滑轨进入红区时，滑块停在红区边缘，一次手势只记一次拒绝。
- **引导**：每关只有一行目标；「提示」按钮分 3 级逐步给信息（`H` 键同效），使用次数计入记录。连续被挡 3 次时，滑轨轻轻脉动（第 0、1 章还会附一句话）。

### 美术

暗色发光玻璃风格：深夜蓝背景，磨砂玻璃物体带菲涅尔边缘光、按 W 着色，暖白光点配光晕和拖尾，金色终点光柱，物体进入切片时有扩散波纹和音效。标题页用 CSS 画五层叠片，一片发光切片在其中扫动（遵守 `prefers-reduced-motion`）。

## 几何

物体是四维超球 `(x−cx)²+(y−cy)²+(z−cz)²+(W−cw)² ≤ R²` 和四维方块。滑轨 `u ∈ [0,1]` 映射为 `W = 4(u − 0.5)`。

- 超球截面：`d = |W − cw|`，`r = √((R − d)(R + d))`（d < R 时）；d = R 为点，d > R 为空。
- 方块截面：`|W − cw| ≤ halfW` 时是完整的三维方块，否则为空。
- W 地图足迹（行走高度 y）：超球 → (x, z, W) 中半径 `√(R² − (y − cy)²)` 的球（比 R 小）；方块 → `|y − cy| ≤ halfY` 时的 (x, z, W) 方块。
- 扁平国（`flatVariant`）把物体中心的 y 对齐到光点高度，所以画出的二维形状恰好就是碰撞边界（有测试保证）。

移动合法性只看当前截面：光点（半径 0.22 的球）不得与任何截面体相交；沿墙按轴滑动。改变 W 时检查整个滑程中每个物体的最大截面，会把光点包进墙里的 W 变更会被拒绝（`wChangeEngulfs`）。W 动画还没走完时，走路同样按「当前显示的 W 到目标 W」之间的最大截面判断（`sweptSections`），光点不会在动画期间走进即将出现的墙。


## 证据边界

脚本通关只证明实现正确、关卡可解，不证明真人能自己想到换 W，也不证明他们理解第四维。双视图和扁平国是按现有作品的经验做出的设计，效果仍需真人检验。下一步建议找没玩过的人，不给任何解释直接从标题页开始，记录：

- 在哪一关第一次主动换 W（G2/G3）；
- 第 2 章的窥视次数和提示使用次数（迁移，G4）；
- 通关后能否用自己的话解释「为什么墙不见了」（G1）。

游戏的「保存记录」JSON 已包含被挡次数、W 调整次数、拒绝次数、W 范围、提示、窥视和预测结果，可直接作为试玩记录。
