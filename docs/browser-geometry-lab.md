# 浏览器四维切片实验

这轮实验对应 [mechanic-validation.md](mechanic-validation.md) 的阶段 B：用一个固定的四维定义生成连续、可观察的三维截面。代码位于 `web/geometry-lab/`，可以在没有 Unity 的电脑上修改、运行和测试。

## 启动与操作

在仓库根目录运行：

```bash
./scripts/preview-geometry-lab.sh
```

打开 <http://127.0.0.1:4175>。启动依赖 Python 3，画面依赖浏览器 WebGL；没有 npm 包、CDN、字体下载或远程服务。模块需要经 HTTP 加载，请使用启动脚本打开。服务只监听本机，Ctrl+C 停止。

端口被占用时可换一个：

```bash
LAB_PORT=4180 ./scripts/preview-geometry-lab.sh
```

- 拖动 W 滑块改变截面；页面空白处按左右键也可微调。
- 拖动画面旋转视角，滚轮缩放。画面获得键盘焦点后，方向键旋转，加减键缩放。
- 自动往返用于连续观察。切到后台会停止自动往返。
- “单个超球”观察从无到有再到消失；“错位双球”观察两个固定物体在同一 W 下的不同截面。
- “截面通道”把同一套截面变成碰撞：方向键 / WASD / 屏幕方向键移动光点，两堵三球墙各居一段 W，只有换 W 才能先后放行。通道模式下自动往返关闭，方向键改为移动光点。
- “预测挑战”先锁定判断，再显示目标位置的截面。六轮覆盖出现、增大、缩小、消失、对称位置同样大，以及一个改变 W 中心和半径的超球。
- 完成后可保存本轮 JSON，含物体定义、起止 W、预测、实际变化和正确数。通道到达出口后可保存移动距离、被挡次数、W 调整次数和 W 范围。刷新页面会清除本轮状态；没有自动上传或持久化。

## 几何来源

每枚超球都保存四维中心 `(cx, cy, cz, cw)` 与固定半径 `R`。归一化滑块 `u ∈ [0,1]` 映射为物理坐标 `W = 4(u − 0.5)`。

四维球体满足：

```text
(x − cx)² + (y − cy)² + (z − cz)² + (W − cw)² ≤ R²
```

固定 W 后，三维截面的中心是 `(cx, cy, cz)`，半径为：

```text
d = |W − cw|
r = √((R − d)(R + d))    当 d < R
```

`d = R` 时相切为一个点，`d > R` 时没有交集。计算模块分别保留 `sphere`、`point` 和 `empty` 三种状态。画面只绘制有体积的球体；相切点或极小半径可能小于像素，不能以截图区分数学上的空集和单点。

渲染器根据这个半径求视线与球面的交点。网格、光照和阴影只帮助观察空间形状。两个错位超球各有固定的四维定义，滑块不会改写它们的中心或半径。

## 通道合法性

截面通道对应 mechanic-validation.md 的阶段 C：通路不由关卡表或 WRange 边决定，而完全由当前截面几何决定。六枚超球排成两堵墙，分别位于 W = −1 与 W = +1；滑块走到哪一片，哪一堵墙就在这一片里存在。

光点是半径 0.22 的小球，移动合法当且仅当目标位置在场地边界内且不与任何截面球相交（三维球-球检测，`tokenInsideSection` / `legalCorridorSpot` / `moveCorridorToken`）。沿墙滑动按轴分离尝试；被完全挡住计入统计。移动 W 时按整个滑程检查每堵墙的最大半径，若新截面会包住光点则拒绝这次滑动——光点不会被墙吞没。

设计上没有任何一个 W 能让直线通路成立：近墙只在 W ≥ +0.15 时消失，远墙只在 W ≤ −0.15 时消失，而中间区域在两墙之间留有安全站位，因此必须先走到两墙之间、再换 W 缩小另一堵。这条性质由逻辑测试固定（`corridor route is only solvable by changing W mid-run`）。

| 文件 | 职责 |
|---|---|
| `geometry.mjs` | 四维定义、W 映射、截面、变化分类、通道布局与移动合法性 |

| `app.mjs` | 滑块、模式切换、动画、通道移动与吞没保护、下载 |

运行逻辑测试需要 Node.js 18+，无需安装包：

```bash
node --test web/geometry-lab/tests/geometry.test.mjs
```

测试还会在四个四维定义上采样 1,872 个截面表面点，检查它们是否满足各自的四维球面方程；通道测试固定两墙封死、各自 W 侧开放、中途必须换 W 和吞没检测。浏览器中需检查单球与双球、端点空截面、自动往返与暂停、视角旋转、完整挑战、通道走通与吞没拒绝、结果下载，以及窄屏布局。页面静止时不持续渲染，画面像素比上限为 1.75，宽度上限为 1,600 渲染像素；这些是实现约束，帧率提升仍需设备实测。

## 本轮证据能说明什么

几何测试用于确认截面来自统一四维方程。预测挑战提供一个可试玩的练习流程；固定题序与即时反馈适合形成初步理解，不能单凭正确率认定玩家已经通过 G0–G4，也不能把自动化脚本操作当成玩家观察。

通道实验说明：在同一套四维方程下，"当前截面的几何"足以独立充当移动合法性来源，不需要任何关卡图或 WRange 边。这与阶段 C 的问题一致，但证据范围是浏览器 spike——Unity 场景里的 mesh 截面与 collider 仍未验证，本实验也不包含 Impossible Room。

建议下一轮让玩家在没有引导的情况下试走通道，记录他们是否主动换 W、如何描述被挡原因。如果这套规则在玩家手中可读，再把相同方程接入独立 Unity scene，验证截面 mesh 与 collider；按现有计划单独推进阶段 D。
