# 给 LLM 的设计理念与试玩评审 Prompt

将下面整段交给支持访问 GitHub、运行项目和操作浏览器的 LLM。没有运行能力时，也可以做代码评审，但必须标明未实际试玩。

```text
请作为空间解谜游戏设计师兼试玩评审者，体验并评估这个项目：

仓库：https://github.com/Fighter-LHL/4D
当前版本分支：codex/courtyard-risk-feedback
代码入口：https://github.com/Fighter-LHL/4D/tree/codex/courtyard-risk-feedback/web

先报告实际读取的提交 SHA。当前开发版本是 web/ 中的原生 HTML、CSS、JavaScript、Canvas 2D 和 Web Audio 游戏；仓库里的 Unity 工程是历史原型，不作为本次试玩对象。

【设计理念】
目标是让玩家在好奇、试错和发现中建立高维空间直觉：先想再试一次、换个角度看看，再逐渐理解几何规则。我们希望它是一款可反复把玩的空间游戏。

1. 用可操控的空间变化表达概念。平面国里，玩家在 XY 平面移动，连续改变切片高度 S，观察三维物体截面的出现、膨胀、收缩与消失。越墙、遮挡、俯视、旋转和手性翻转需要产生可观察、可预测的后果。进入庭院后，把这一直觉迁移到 XYZ 空间中的连续 W 切片。
2. 把发现变成新玩法。探索获得的伙伴能让玩家继续试验规则：跳跳探向上层、同层或下层，触碰机关、拾取并引开守卫；瞌睡灯显出附近上下层的真实截面；反反在镜像位置同步，受真实地形阻挡。六个场景的伙伴机关应结合当地地形，让玩家运用已有理解。
3. 让收集成果留下痕迹。每座花园的三枚花种全部收齐后留下开花记录，六园全开解锁花冠与纪念印记。伙伴与花冠可以进入庭院，风暴中也能陪伴和应援，让探索成果在其他玩法中仍可见。
4. 区分自由探索和计分挑战。默认探索允许放松试验、停留和收集；挑战与风暴强调精确操作、判断和可复现成绩。伙伴能力仅用于探索；风暴应援只改变画面，不能改变碰撞、拾取、随机序列或得分。
5. 保留玩家自己发现路线的空间。庭院围绕同位换层、跨层供能、双源汇流、远端折返和遗物组合展开。伙伴平时跟随，主动询问或闲置后只给当前一步短提示。帮助应降低卡顿，避免替玩家解完整道题。
6. 用顺手的操作支撑观察。反馈尽量发生在场景中，文字短而与当前动作有关。鼠标、键盘和窄屏操作都要可用；暂停应真正冻结游戏；失败应能快速重试并理解原因。视觉方向是克制、温暖、清晰的几何小世界，收集成功与危险反馈应有层次。

【当前实现与边界】
平面国包含访客、变形锁、越墙、潜入、镜之锁、升维六个场景，以及风暴无尽挑战。庭院从手工模板中抽取三庭，跨庭积累遗物并组合捷径与风险收益。庭院使用预设实体的连续 W 截面与通行规则，当前不是任意四维物理模拟器。

截面弹射、可推动三维遮体、无缝连廊、风暴伙伴战斗加成属于潜在方向，不应当作已经实现的功能。

【如何运行】
git clone --branch codex/courtyard-risk-feedback https://github.com/Fighter-LHL/4D.git
cd 4D/web
npm start

需要 Node.js 18+，无需安装 npm 依赖。打开：
- 平面国：http://127.0.0.1:4173/flatland.html
- 庭院：http://127.0.0.1:4173/

另一个终端在 web/ 下运行 npm test。GitHub 链接是代码入口，不代表已经部署在线试玩页面。

平面国：WASD / 方向键 / 按住画面拖动移动；Q、E / 滚轮 / 滑条调 S；Shift 精调；B 使用已同行伙伴的能力；C 循环跳跳方向；V、Space、F 按关卡提示使用；P / Esc 暂停，R 同题重来。
庭院：Z / X / C 快速换层，A / D 或滑条连续调 W；点击平台先预览，再点已选可达平台稳行；Space 或按钮穿越；E 启动机关；H 询问伙伴。相同种子可复现布局与规则，不恢复半局进度。

【试玩方式】
先用新档体验，不读攻略，不预写收藏存档，不直接修改模型来制造通关。记录第一次不知道该做什么、一次误操作、一次发现规律和一次想重试的具体时刻；遇到卡点先观察场景反馈，再使用提示。随后可以阅读 README、代码和已有验证记录定位原因。新档请使用隔离的浏览器环境，保留用户原存档。

至少体验以下闭环，无法完成的明确说明停在哪里：
- 前两关的移动与截面目标是否真的相互配合。
- 自己找到伙伴，使用一次能力，完成一座花园，再比较其他场景的解法是否有变化。
- 只有实际完成六园后，才评价全收集庆祝与跨场景花冠的实测效果。
- 从升维进入庭院，观察空间直觉是否能迁移；检验提示是否抢走解谜过程，以及首次点击预览、再次点击稳行是否直觉。
- 风暴里经历危险预警、受击、重试；能完成擦身或高连击时再检查伙伴应援。
- 在桌面与 320 / 390px 窄屏检查提示遮挡、点击误触、侧视图可读性、暂停和减少动态效果。

【输出要求】
请给出独立判断，不复述设计愿景来代替试玩结论：
1. 实际版本、环境、试玩路径、用时、完成与未完成范围。
2. 三个最有效的体验，说明具体动作、反馈及产生的判断。
3. 最影响理解或重玩意愿的五个问题，按严重度排序；每项给复现步骤、种子/模式/视口、实际与预期行为、截图或代码位置。
4. 在现有 model / geometry / perception / scene / input 职责分离下，提出三项成本低、收益明确的改进，分别说明玩家价值、最小改动和验收方法。
5. 分开标记“浏览器实测”“代码推断”“尚待真人验证”。测试通过只能证明对应规则检查通过，不能证明玩家觉得有趣。

这轮先评审并提出建议，不自动改代码、重构、部署或替我做发布决定。如果没有浏览器能力，明确只进行了代码推断，不编造试玩过程。
```
